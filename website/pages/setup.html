  • You have a terminal: Terminal on macOS and Linux, PowerShell or Windows Terminal on Windows. All of them know ssh.

The four steps

  1. Log in

    Pick a GPU cluster. Alpha has A100 GPUs, Capella has H100 GPUs. Both work for everything in this lab.

    ssh @login1.alpha.hpc.tu-dresden.de # GPU cluster, 8 A100 per node ssh @login1.capella.hpc.tu-dresden.de # GPU cluster, 4 H100 per node ssh @login1.barnard.hpc.tu-dresden.de # CPU cluster

    The first time, ssh asks if you trust the machine. Compare what it shows with the key fingerprints in the Compendium and answer yes. Then type your ZIH password. Nothing appears while you type, that is normal.

    Optional: log in without typing the password every time

    Create a key pair on your own computer and copy the public half to the cluster. Give the key a passphrase when you are asked.

    ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 ssh-copy-id -i ~/.ssh/id_ed25519.pub @login1.alpha.hpc.tu-dresden.de

    Windows has no ssh-copy-id. Copy the file over and add it by hand:

    ssh-keygen -t ed25519 scp $env:USERPROFILE\.ssh\id_ed25519.pub @login1.alpha.hpc.tu-dresden.de: ssh @login1.alpha.hpc.tu-dresden.de mkdir -p ~/.ssh && cat id_ed25519.pub >> ~/.ssh/authorized_keys && rm id_ed25519.pub

    More about keys and ssh settings is in the Compendium.

  2. Get the lab kit

    You are now on a login node. Clone the repository into your home folder. It is small.

    git clone {{clone}} cd behind-llms-lab/hpc_lab

  3. Build the Python environment

    Installing PyTorch is real work, so it does not belong on the login node. Ask Slurm for a small interactive job, run the setup script there, and give the machine back.

    srun --account=p_scads_lv_llm --ntasks=1 --cpus-per-task=4 --mem-per-cpu=2G \ --time=00:45:00 --pty bash -l # a small interactive job cd ~/behind-llms-lab/hpc_lab source 00_setup/setup_env.sh # workspace, venv, training text exit # give the machine back

    The first run takes 5 to 10 minutes. At the end you should see something like this:

    workspace : /data/horse/ws/-llm-lab creating the venv /data/horse/ws/-llm-lab/venv-llm (only the first time, this takes a few minutes) python : /data/horse/ws/-llm-lab/venv-llm/bin/python (Python 3.12.3) downloaded tiny Shakespeare to /data/horse/ws/-llm-lab/data/input.txt environment ready

    Use source, not bash. Only then does the environment stay switched on in your shell. From now on the same line takes a second, and the job scripts run it themselves.

  4. Check that it works

    Send the first job of the lab. It needs no GPU and only runs for a few seconds once it starts.

    cd ~/behind-llms-lab/hpc_lab/01_hello mkdir -p logs && sbatch hello.sbatch squeue --me # PD means waiting, R means running cat logs/hello-hpc-*.out # when the job is gone from the queue

    If the log shows the name of a compute node and an estimate of pi, you are ready for the HPC lab.

The setup script

00_setup/setup_env.sh does five things, and it is safe to run as often as you like:

  1. It creates the workspace llm-lab, or reuses it. This is the big, fast storage for the environment, the data and the models.
  2. It loads a Python module of the cluster.
  3. It creates a virtual environment with PyTorch and transformers inside the workspace, or switches it on if it is already there.
  4. It points the pip, Hugging Face and temporary caches into the workspace, away from the small home folder.
  5. It downloads the tiny Shakespeare text that exercise 4 trains on.

It also sets $WS_DIR, the path of your workspace. The job scripts use it for data and results.

Your own experiments

The lab kit is meant to be taken apart. Once the seven exercises work, the same pieces run your own code.

  1. Code goes into your home folder, everything big goes into the workspace. After source 00_setup/setup_env.sh the workspace is $WS_DIR. The lab uses $WS_DIR/data for data and $WS_DIR/runs for results.
  2. Need another package? Start an interactive job as in step 3, switch the environment on and install it. It lands in the environment in your workspace and every later job has it.
  3. Write a job script. Copy the one from the exercise that is closest to what you want and change the last line, or use the generator below.
  4. Send it and watch it. sbatch, squeue --me, tail -f logs/…. The cheat sheet has the rest.
srun --account=p_scads_lv_llm --ntasks=1 --cpus-per-task=4 --mem-per-cpu=2G --time=00:30:00 --pty bash -l source ~/behind-llms-lab/hpc_lab/00_setup/setup_env.sh pip install datasets # or whatever you need exit

This job script generator needs JavaScript. Without it, copy hpc_lab/04_tinygpt/train.sbatch and change the last line.

Habits worth copying from the lab scripts

  • Create logs/ before you submit. If the folder for the log file is missing, the job ends at once and leaves no trace.
  • Print with flush=True or run python -u. Otherwise the log stays empty until the buffer is full.
  • Save a checkpoint when Slurm says stop. Slurm sends SIGTERM when you cancel a job or when the time is over. train_tinygpt.py catches it and saves, and --signal=TERM@60 makes the signal come 60 seconds early.
  • Ask for what you need, not more. A job that asks for less time and fewer GPUs starts sooner.
  • Download models on the login node first. Then set HF_HUB_OFFLINE=1 in the job, as exercise 6 does, so the job uses the copy in your workspace.
  • Sweeps are job arrays. One script, one line --array=0-3, and $SLURM_ARRAY_TASK_ID picks the setting. See exercise 5.

A separate workspace for another project

The setup script takes its settings from the environment. To keep a project apart from the lab, give it its own workspace. Jobs you send from the same shell use it too.

unset WS_DIR # forget the lab workspace in this shell export WS_NAME=my-project source ~/behind-llms-lab/hpc_lab/00_setup/setup_env.sh

The course project is for the course. Jobs with --account=p_scads_lv_llm are booked on the course. For your thesis or your own research, ask your supervisor which HPC project to use and put its name there.
