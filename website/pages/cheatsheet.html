Job states

CodeStateMeaning
PDpendingWaiting in the queue. The REASON column says why.
RrunningIt has its resources and is working.
CGcompletingFinished, Slurm is cleaning up.
CDcompletedEnded without an error.
FfailedThe program ended with an error. Read the .err file.
CAcancelledStopped with scancel.
TOtimeoutIt hit the time limit.
OOMout of memoryIt used more memory than it asked for.

A job script, line by line

#!/bin/bash #SBATCH --job-name=tinygpt # the name you see in squeue #SBATCH --account=p_scads_lv_llm # the project that pays for the time #SBATCH --ntasks=1 # one process #SBATCH --cpus-per-task=6 # CPU cores that come with the GPU #SBATCH --gres=gpu:1 # this is the line that gets you a GPU #SBATCH --mem=32G # memory for the whole job #SBATCH --time=00:30:00 # hard time limit, hh:mm:ss #SBATCH --signal=TERM@60 # send SIGTERM 60 s before the time limit #SBATCH --output=logs/%x-%j.out # %x is the job name, %j the job ID #SBATCH --error=logs/%x-%j.err # the logs folder has to exist before you submit source ~/behind-llms-lab/hpc_lab/00_setup/setup_env.sh # workspace, modules, venv export SRUN_CPUS_PER_TASK=$SLURM_CPUS_PER_TASK # pass all cores on to the program srun python -u my_script.py # -u: print without buffering
Also usefulWhat it does
--mem-per-cpu=2GMemory per core, instead of --mem for the whole job.
--array=0-3Start the script 4 times. $SLURM_ARRAY_TASK_ID goes from 0 to 3. With 0-3%2 at most 2 run at the same time.
--output=logs/%x-%A_%a.outFor arrays: %A is the array job ID, %a the task number.
--dependency=afterok:<jobid>Start only after another job has finished without errors.
--begin=now+5minutesDo not start before this time.
--parsableMake sbatch print only the job ID, to keep it in a shell variable.
--export=ALL,NAME=valueHand an extra variable to the job.

When something goes wrong

What you seeWhat it usually is
The job ends at once and there is no log file.The logs/ folder is missing. Run mkdir -p logs.
CUDA available: FalseYou forgot --gres=gpu:1, or you sent the job from Barnard.
Disk quota exceeded in $HOMEThe pip or Hugging Face caches are in your home folder. source 00_setup/setup_env.sh moves them to the workspace.
module load failsModule versions change about twice a year. Run module spider Python and change PY_MODULES in setup_env.sh.
OUT_OF_MEMORY in sacctAsk for more memory with --mem.
The job waits for a long time.Ask for less time or fewer GPUs, and check whypending <jobid>.
The log stays empty while the job runs.Python is buffering. Use python -u or print(..., flush=True).
WS_DIR: run source ../00_setup/setup_env.sh first$WS_DIR is not set in this shell. Do what the message says.
A model cannot be found in a job with HF_HUB_OFFLINE=1It was never downloaded. On the login node: python generate.py --download-only --model <name>.
ssh does not connect at allYou are not on the university network. Start the VPN.
