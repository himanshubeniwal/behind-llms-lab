Cheat sheet

Every command of the lab on one page: Slurm, job scripts, workspaces, and what to do when something goes wrong.

Log in#

Every cluster has its own Slurm, so GPU jobs have to be sent from an Alpha or Capella login node. Our project (account) is p_scads_lv_llm.

Slurm commands#

What you wantCommand
see partitions and free nodessinfo, sinfo -s, sinfo -o "%20P %5a %10l %6D %20G"
send a batch jobsbatch job.sbatch
Options on the command line win over #SBATCH lines.
a terminal on a compute nodesrun --account=p_scads_lv_llm --ntasks=1 --cpus-per-task=2 --mem-per-cpu=2G --time=00:30:00 --pty bash -l
the same with a GPUadd --gres=gpu:1
On Alpha, for quick tests: --partition=alpha-interactive
my jobssqueue --me
with the expected start time: squeue --me --start
why is my job waiting?whypending <jobid> (a ZIH helper) or scontrol show job <jobid>
cancelscancel <jobid>
one array task: scancel <jobid>_3
all of mine: scancel -u $USER
what did it use?sacct -j <jobid> --format=JobID,JobName,State,Elapsed,MaxRSS,ExitCode
change the time limitscontrol update timelimit=00:20:00 jobid=<jobid>
Normally you can only make it shorter.
watch a log while the job runstail -f logs/<name>-<jobid>.out
Ctrl+C stops tail, not the job.

Job states

CodeStateMeaning
PDpendingWaiting in the queue. The REASON column says why.
RrunningIt has its resources and is working.
CGcompletingFinished, Slurm is cleaning up.
CDcompletedEnded without an error.
FfailedThe program ended with an error. Read the .err file.
CAcancelledStopped with scancel.
TOtimeoutIt hit the time limit.
OOMout of memoryIt used more memory than it asked for.

A job script, line by line#

Also usefulWhat it does
--mem-per-cpu=2GMemory per core, instead of --mem for the whole job.
--array=0-3Start the script 4 times. $SLURM_ARRAY_TASK_ID goes from 0 to 3. With 0-3%2 at most 2 run at the same time.
--output=logs/%x-%A_%a.outFor arrays: %A is the array job ID, %a the task number.
--dependency=afterok:<jobid>Start only after another job has finished without errors.
--begin=now+5minutesDo not start before this time.
--parsableMake sbatch print only the job ID, to keep it in a shell variable.
--export=ALL,NAME=valueHand an extra variable to the job.

Variables inside a job

VariableHolds
$SLURM_JOB_IDThe job ID.
$SLURM_CPUS_PER_TASKThe number of cores you asked for.
$SLURM_ARRAY_TASK_ID, $SLURM_ARRAY_JOB_IDThe number of this task in an array, and the ID of the whole array.
$SLURM_JOB_NODELISTThe node or nodes the job runs on.
$WS_DIRYour workspace. Set by setup_env.sh, not by Slurm.
$HF_HOMEWhere Hugging Face keeps models. setup_env.sh points it into the workspace.

Workspaces#

What you wantCommand
create or reusews_allocate -F horse llm-lab 30
prints /data/horse/ws/<user>-llm-lab
listws_list
extendws_extend -F horse llm-lab 30
This sets the remaining time to 30 days. It does not add 30 days.
deletews_release -F horse --name llm-lab
e-mail reminderws_allocate -F horse -r 7 -m <you>@tu-dresden.de llm-lab 30

Keep data, models and caches out of $HOME. It is small and backed up, so it fills up fast.

When something goes wrong#

What you seeWhat it usually is
The job ends at once and there is no log file.The logs/ folder is missing. Run mkdir -p logs.
CUDA available: FalseYou forgot --gres=gpu:1, or you sent the job from Barnard.
Disk quota exceeded in $HOMEThe pip or Hugging Face caches are in your home folder. source 00_setup/setup_env.sh moves them to the workspace.
module load failsModule versions change about twice a year. Run module spider Python and change PY_MODULES in setup_env.sh.
OUT_OF_MEMORY in sacctAsk for more memory with --mem.
The job waits for a long time.Ask for less time or fewer GPUs, and check whypending <jobid>.
The log stays empty while the job runs.Python is buffering. Use python -u or print(..., flush=True).
run 'source ../00_setup/setup_env.sh' first$WS_DIR is not set in this shell. Do what the message says.
A model cannot be found in a job with HF_HUB_OFFLINE=1It was never downloaded. On the login node: python generate.py --download-only --model <name>.
ssh does not connect at allYou are not on the university network. Start the VPN.

Documentation: compendium.hpc.tu-dresden.de. Support: hpc-support@tu-dresden.de.
